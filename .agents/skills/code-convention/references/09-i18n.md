# 09 — Internationalization and notifications

Every user-visible string is an i18n key; `ThongBao` is the only path to a dialog.

## Key shape

`app.<module>.<camelCase>`, where `<module>` is one of:

`title`, `menu`, `menuGroup`, `localeName`, `common`, `enum`, `date`, `khachHang`, `nhanVien`, `xe`, `phuTung`, `dichVu`, `phieuTiepNhan`, `tiepNhan`, `khieuNai`, `voucher`, `phieuNhap`, `chanDoan`, `login`, `dashboard`

Shared keys live in `app.common` (`notification`, `error`, `loiKhongXacDinh`, `confirm`, `cancel`, `add`, `save`, `delete`, `clear`, `edit`, `search`, `all`, `actions`, `count`, `next`, `prev`, `pageLabel`). Date formats and picker labels live in `app.date`. Enum labels are generated as `app.enum.<Enum>.<CONSTANT>` by `I18nEnum`.

## ThongBao API

| Need | Call |
|---|---|
| Success / information | `thongTin(parent, key)` |
| Information with arguments | `thongTinDinhDang(parent, key, args…)` (MessageFormat) |
| Input warning | `canhBao(parent, key)` |
| Error from a key | `loi(parent, key)` |
| Error from an exception | `loi(parent, ex)` — uses `ex.getMessage()` as the key, falls back to `app.common.loiKhongXacDinh` |
| Yes / no | `xacNhan(parent, keyNoiDung, keyTieuDe)` — honour the boolean |

## Rules

R1. Pass keys, not text. For a label used while building the UI, resolve with `I18nReaderUtil.get(key)` at build time; for a dialog, pass the key to `ThongBao`.

R2. Never build `JOptionPane` directly. The only exception is a typed input dialog (`AnhField`'s `showInputDialog`).

R3. Add, remove, and rename keys in `src/resources/i18n_vn.json` and `src/resources/i18n_en.json` in the same change, inside the matching module object.

R4. Both files must have identical key sets. No orphan keys, no duplicate keys, no key reused for different text, no reformatting of untouched lines.

R5. A key means one thing. If two screens need different wording, they need different keys.

R6. Exceptions carry keys, never sentences: `IllegalArgumentException(ERROR_X)`, then `ThongBao.loi(parent, ex)`. `SQLException` maps to `app.login.errorSystem` at the call site.

R7. Confirm before destructive or irreversible actions (delete, clear with unsaved edits, finalize money/stock); stop immediately when `xacNhan` returns `false`.

R8. Enum-valued combos use `I18nEnum` + `BoHienThiI18n.tao()`, so no label is duplicated in a screen.

R9. A screen that must follow a locale change re-renders (`render()`, `MenuRegistry.refreshText()`) instead of caching translated strings in fields.

## Reference code

- `src/iuh/fit/gui/component/ThongBao.java` — the six entry points.
- `src/iuh/fit/util/I18nReaderUtil.java#get` — flat lookup from nested JSON.
- `src/iuh/fit/enumeration/I18nEnum.java` — `app.enum.<Enum>.<CONSTANT>`.
- `src/iuh/fit/gui/component/BoHienThiI18n.java` — combo renderer with the "all" option.
- `src/iuh/fit/gui/page/LoginPage.java#dangNhap` — exception/sqlkey mapping.
- `src/resources/i18n_vn.json`, `src/resources/i18n_en.json` — key source of truth.

## Anti-patterns

- `ThongBao.loi(this, "Không lưu được dữ liệu")`.
- `JOptionPane.showMessageDialog(...)` in a page.
- A key present in `i18n_vn.json` but missing from `i18n_en.json`.
- Reusing `app.common.delete` for a confirmation sentence and a button label.
- Catching `AuthException` and showing a hardcoded message instead of its key.

## Check

```bash
python3 - <<'PY'
import json
def leaves(o, p=""):
    out = set()
    for k, v in o.items():
        if isinstance(v, dict):
            out |= leaves(v, p + k + ".")
        else:
            out.add(p + k)
    return out
vn = leaves(json.load(open("src/resources/i18n_vn.json")))
en = leaves(json.load(open("src/resources/i18n_en.json")))
print("only vn:", sorted(vn - en))
print("only en:", sorted(en - vn))
PY
grep -rn 'JOptionPane' src/iuh/fit/gui | grep -v ThongBao | grep -v AnhField   # expect: none
```
